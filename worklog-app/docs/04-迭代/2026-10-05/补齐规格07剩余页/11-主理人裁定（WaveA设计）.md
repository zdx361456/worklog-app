### 9.2 ★ E-14（**第三次**设计自引入缺陷，危害最大）：公司名被截成 2 个字

| 事实 | 证据（我已逐条实测） |
|------|---------------------|
| **`shortName` 在本 App 无任何 UI 可设置** | 新建公司写死 `shortName: null`（`company_page.dart:161`）；编辑对话框仅透传（`:201`/`:372`、`company_detail_page.dart:167`）；**全仓唯一可能赋非 null 的路径是备份导入**（`import_service.dart:307`） |
| `displayName` **简称非空取之，否则取 `name` 前 2 字** | `models/company.dart:40-45`（`runes.take(2)`） |
| 该值被用作 **4 个页面的公司主标签** | `overview_page.dart:471` / `company_page.dart:510` / `company_detail_page.dart:297` / `debt_list_page.dart:383` |
| **后果** | 两家名称前两字相同的公司（「某某建筑」/「某某劳务」）在**欠款列表里显示成同一个词 → 用户分不出欠谁的钱**；在 P06 更是**相对改动前的回退**（改前 tile 用全名） |

**根因（我的责任，留痕）**：源头是**我自己的裁定 `E-4` / `M-13③`**——我判定 `company.shortName ?? company.name` 与 `displayName` 等价，指令设计方"丢弃前式、统一用后者"。
**它们并不等价**：`shortName ≡ null` 时**前者 = 全名**、**后者 = 2 字**。
`M-13③` 字面禁止的 `shortName ?? company`（`String? ?? Company`）本是一个**类型错误**的写法，我把"纠正类型错误"过度推广成了"改用 `displayName`"。
**教训（第 4 条，本批新增）**：**判断两个表达式等价前，必须先问"这个字段在真实数据流里到底有没有人写它"**——字段语义等价 ≠ 取值等价。

### 9.3 裁定 **R-14**（公司名展示口径 · 定论）

1. **公司名主标签一律用全名 `company.name`**；**`shortName` 非空时**以「（简称）」追加（满足 `07:218`「公司名 + 短名」的字面语义）。四处表达式**逐字统一**：
   ```dart
   final label = (c.shortName == null || c.shortName!.isEmpty)
       ? c.name
       : '${c.name}（${c.shortName}）';
   ```
2. **撤销 `E-4` / `M-13③` 中"统一用 `displayName`"的部分**；`09 §16` 的 `grep "shortName ?? company"` 自检项**作废**，改为 `grep "displayName"` 在这 4 个 UI 文件 **0 命中**。
3. **`models/company.dart` 的 `displayName` 保留不删、不改**——它是**窄格场景**的短标签，留给 Wave C 的 P03 日历格用；本波只是**不在主标签位使用**它。
