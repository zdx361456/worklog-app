## 3. 恒等式验算（第 2 项）

**三处新口径**（`02:174` / `02:182` / `02:823`）统一为：
- 顶部「**欠款合计**」= `Σ 列表内 remaining`，**列表仅含 `remaining > 0` 的公司**；
- 恒等式：`欠款合计 − |多收合计| == aggregate(null).remaining`。

**构造数据**：A 欠 **1000**、B 欠 **500**、C **多收 200**（即 C 的 `remaining = −200`）。

| 量 | 计算 | 结果 |
|----|------|:---:|
| 列表内容（仅 `remaining > 0`） | {A, B}（C 不入列） | — |
| 欠款合计 | 1000 + 500 | **1500** |
| 多收合计的绝对值 | \|−200\| | **200** |
| `aggregate(null).remaining` | 1000 + 500 + (−200) | **1300** |
| **恒等式** | 1500 − 200 | **1300** ✓ |

**验算结论**：
1. **恒等式数学成立**（通式：`aggregate(null).remaining = Σ_all remaining = Σ_{remaining>0} remaining + Σ_{remaining<0} remaining = 欠款合计 − |多收合计|`；`remaining == 0` 的公司贡献 0，不影响）。前提是 `aggregate(null).remaining == Σ aggregateByCompany().remaining`（`02:213` 已声明，`07 §1.8-3`）。
2. **三处口径彼此自洽**：均把「欠款合计」定义为"列表内正 `remaining` 之和"，且均明写**不得**等于 `aggregate(null).remaining`。
3. **旧断言确实必假**：旧口径 `欠款合计 == aggregate(null).remaining` 在存在多收公司时得 `1500 ≠ 1300`，故 N-2 的修正是必要且正确的。
