- **现象**：裁定让 4 个页面的公司主标签改用 `Company.displayName`，理由称「与 `shortName ?? name` 等价」——**实际不等价**。结果：`shortName` 全 App **无任何 UI 可写入**（新建公司写死 `shortName: null`，`company_page.dart:161`；编辑框仅透传 `:201`/`:372`；**全仓唯一可能赋非 null 的路径是备份导入**，`import_service.dart:307`），故 `displayName`（`models/company.dart:40-45`，`runes.take(2)`）= **始终取 `name` 前 2 字**，而 `shortName ?? name` 在 `shortName ≡ null` 时 = **全名**。→ 4 个页面的公司主标签被截成 2 字（`overview:471` / `company_page:510` / `company_detail:297` / `debt_list:383`），「某某建筑」与「某某劳务」显示成同一个词，**用户分不出欠谁的钱**；在 P06 更是相对改动前的**回退**（改前 tile 用全名）。
- **根因**：源头是主理人**自己的裁定 `E-4` / `M-13③`**——把 `M-13③` 字面要纠正的一个**类型错误写法**（`String? ?? Company`）过度推广成「统一改用 `displayName`」。**字段语义等价 ≠ 取值等价**。
- **处置留痕**：裁定 **R-14**（主标签用全名 `name`，`shortName` 非空时追加「（简称）」；`displayName` 保留给 Wave C 的 P03 日历窄格，**不删不改**）→ 补丁 **S1** 下发 4 线各改 1 处；`09 §6.3.1` 就地开**勘误 E-14**（同源作废另有三处 `§6.7`/`§7.4`/`§9.2`）。
- **硬规则**：**判断两个表达式等价前，必须先问「这个字段在真实数据流里到底有没有人写它」。**

### 4.2 第 2 类 · 跨线串项（本批最重要的流程教训）

- **现象**：主理人给 `impl-p06` 下发的偏差裁定里，**#1 表述错、#3/#4 两项根本不存在**：声称「停用/归档行用 `lineThrough`」→ `grep -rn lineThrough app/lib/ui/` **全目录 0 命中**；声称「『启用中…』用页内局部 bool」→ `启用中` **只存在于 `company_detail_page.dart:378`（P07）**；`_onMenu`（`company_page.dart:308`）实为**三项**（编辑 / 停用·启用 / 删除）。**更糟的是这三条已被写进冻结的裁定件 `11 §9.6`。**
  **后续又发生第 3、4 次（`11 §9.8.1`，由审查官抓出）**：第 3 次——`§9.6` 写「`impl-p07` #3：`corrupted` 时隐藏规则区块 → 接受」，而该线**从未报过**这一条（其 #3 实为"页面级空态 ③ 的判据"）；第 4 次——`§9.6` 写「**接受**——设计**只对 P-DEBT** 要求 `ListView.builder`」，而 `02 §D.0.3:340` 原文的惰性适用范围**明确包含 P01 公司卡片区**。均由 `review-p07` / `review-p01` 抓出。
- **根因**：把 `impl-p07` 报告的偏差项串到了 `impl-p06` 头上；`lineThrough` 在本轮任何证据里都不存在。**多线并行 + 同名术语（"降级/坏值/空态"）反复出现时，凭记忆转述最不可靠**。`impl-p06` **正确地顶了回来**（去读自己的文件 + 给行号，拒绝执行"文件里找不到的现象"）——这是**正确履职**。
- **硬规则**（`11 §9.6` 升级为硬规则）：① 裁定某线偏差前**必须复读该线自己的原文**；② **偏差项一律以「文件 + 行号」为准，禁止凭记忆或凭"刚读过另一条线的报告"转述**；③ **凡引用某线偏差或上游规定，必须"逐字复制原文"，禁止转述**——写裁定行时先把被引用的**原句**粘出来，粘不出来就不写"依据"；④ worker 有权要求给出可查证定位，**拒绝执行查无实据的改动不算不配合**。

### 4.3 第 3 类 · `§9.5` 与 `§9.6` 自相矛盾（同一事实两处定义）

- **现象**：`11 §9.5` 只写「计数**失败时**必须退回不带条数的原文案」，而 `§9.6` 与发给实现方的指令却写成「含**无记录不显示 0 条**…**已实现**」→ 实现方按前者做，**代码里还留了替代码作不实承诺的注释**；最终在**真 0 条**时仍显「0 条 / 0 笔」（= §3.3 MAJ-3 的直接来源）。
- **根因**：把"计数**失败**"与"计数**为 0**"混成了同一句，且**同一事实在文档两处各写一遍**、未做单点定义。`review-p06` 抓为 **MAJ**，主理人一并承认这是**自己的措辞**问题。
- **硬规则**：**同一事实只在一处定义，其它处引用；发现矛盾先改源头再下发。**

### 4.4 第 4 类 · 同源文案分叉（S2 / 勘误 E-15）

- **现象**：同一空态在**标题**与**按钮**两处要求不同字——标题「还没有公司」/ 按钮「先建一个公司」。原设计 `09 §6.7` 把标题**也**改成按钮那句同文案 → 页面出现**标题与按钮两遍同一句话**。
- **根因**：上游 `07:240` **只规定按钮文案**（「先建一个公司」），`AC-P01-11` 亦**只约束「主按钮文案与出口」**；设计 `§6.7` 的「标题也改」属**无上游依据的扩大**。
- **处置留痕**：裁定**补丁 S2**（**按钮不动**、**标题改「还没有公司」**）；`09 §6.7` 就地开**勘误 E-15**；回流 **R18**。
- **硬规则**：**一处文案需求只在规定的控件上生效，不得把"按钮文案"外推到同页其它控件；发现同页同句重复 = 越界扩大的信号。**

### 4.5 第 5 类 · 「同构模拟」冒充「实测」（本轮归档梳理时发现）

- **现象**：证据脚本有一节标题写作「`_guard` **同构验证**」，实际用的是**脚本内逐字复刻的副本**——页内 `_guard` 是**私有实例方法**，脚本根本调不到。即该节**不是**对真实页内 `_guard` 的实测，而是对"同构副本"的推理。
- **根因**：把**同构推理**当成**实测**呈现，未标注证据层级 → 读者会误以为验证了真实实现。**这与前 4 类同源：都是"表述超过了证据能支撑的范围"。**
- **处置**：已被主理人责令**转正**为 `tool/verify_p01_degrade.dart`（现盘存在，8819 B），并要求**三分标注「实测级 / 同构推理 / 读码级」**；`_scratch/verify_p01_degrade.dart`（6881 B）**被 supersede**（不删，见 §6）。
- **硬规则**：**证据必须标注层级；同构推理 ≠ 实测。私有成员无法从外部调用的，一律标注为"同构推理/读码级"，不得写"实测"。**

> **五类的共同母题**：本波所有教训都可归到一句——**"只写能证伪的那一半，且只写证据支撑得住的那一半"**（`11 §5.3` 原话）。E-14 是"等价判断"越界，串项是"引用"越界，§9.5/§9.6 是"单点定义"缺失，S2 是"适用范围"越界，第 5 类是"证据层级"越界。
