### 2.3 数据层能力盘点（关键：下钻**不需要**改 DB 层）

| 能力 | 位置 | 备注 |
|------|------|------|
| 按公司+日期区间+状态查工作记录 | `database.dart:619-633` `listWorkRecords({companyId, startDate, endDate, includeDeleted, includeDraft})` | 含 `...On` / `...Lenient` 变体 |
| 按公司+日期区间查收款记录 | `database.dart:910-922` `listPaymentRecords({companyId, startDate, endDate, includeDeleted})` | 同上 |
| 单公司 / 全局聚合 | `database.dart:273-274` `aggregate(String? companyId)`、`:297-326` `aggregateOn` | |
| 一次查全部公司聚合 | `database.dart:333-334` `aggregateByCompany()`、`:337-380` `aggregateByCompanyOn` | **「谁还欠我钱」视图直接可用** |
| 底层 SQL 过滤 | `database.dart:1250-1274`（`company_id = ?` @1260、`attribution_date` 闭区间 @1258）、`:1277-1299`（`pay_date` @1284） | |
| 索引 | `database_schema.dart:132-138`（`idx_work_record_company_date`、`idx_payment_company_date`） | **公司+日期下钻有现成索引** |

> **结论：`lib/db/database.dart` 在本轮应视为只读冻结层**，下钻功能纯属 UI 接线，不需要改数据层。

## 4. GitHub 同类项目调研结论（U-3 已交付）

调研完成（数据取自 GitHub REST API，2026-10-05）。完整报告见交付记录。要点：

- **「工时/工资/欠薪」方向无可直接复用的成熟开源实现**：`m4ynk-dev/KaamKhata`（定位最贴近，但 `size=1KB` 仅 README 无代码）、`WhiteBrothersky/HourlyWageSmallLedger`（空仓库 0 字节）、`ernestum/Wage-Labor-Record`（GPL-3.0 传染 + Python 桌面）、`dSpringOnion/wagehound`（**无许可证** + 依赖 Supabase 后端，与"纯本地零后端"底线冲突）。→ **反向印证本产品定位是市场空白**。
- **可安全借鉴的实现集中在「记账 App」方向**（Top 3）：
  1. **`devaldaki3/BudgetBudy`**（MIT，103★，**Flutter + sqflite**）——唯一"技术栈 + 数据模型 + 下钻实现"三者同时命中：`getTransactionsByParty(partyId)` 即"点对象看该对象明细"；日/周/月/年/最近五档筛选；余额**自动计算不另存**（与我们"全派生"底线一致）。⚠️ 它用**双库分离**（`spendings.db`+`khatabook.db`），**不可照抄**——我们必须单库 + 公司维度字段，否则跨库无法做统一差额与事务一致。
  2. **`getpoka/poka-ce`**（Apache-2.0，61★，Flutter + Riverpod + GoRouter + Freezed）——"带筛选条件进明细页"的现代路由/状态范式（可 deep-link、可回退）。
  3. **`actualbudget/actual`**（MIT，29,315★，local-first）——"报表 → 下钻 → 派生视图不落库"的范式校准。
- **许可红线（仅可读思路、代码不可抄）**：`firefly-iii`（AGPL）、`kimai`（AGPL）、`Ivy-Apps/ivy-wallet`（GPL + 已归档）、`AndreAle94/moneywallet`（GPL）、`moneymanagerex`（GPL）、`ernestum/Wage-Labor-Record`（GPL）。

**对下钻链路的具体建议**（供 PM/Dev 参考，不替代阶段①②裁定）：
1. 用**不可变值对象**承载筛选条件（`LedgerFilter{type, companyId, dateRange}`，`copyWith`），作唯一筛选真源；
2. 筛选条件走**路由参数**而非全局状态（可回退、可 deep-link）；
3. 明细列表按 filter **派生**每次重算，**绝不新增汇总表**（守"全派生"底线）；
4. DAO 层参数化查询（**参数绑定**，防注入）+ 复用既有 `(company_id, date)` 索引；
5. 明细页顶部显示**可删除的筛选 chips** + 区分"该公司暂无记录"/"该时间段无数据"的空态。
