## D-1 金额一律整数「分」存储，倍率整数「×10」，禁浮点

- **决策**：金额一律以**整数「分」**存储；倍率一律以**整数「×10」**存储；**禁用浮点**。UI 显示与换算一律整数运算；禁 `fen / 100`、`(fen/100).toStringAsFixed(2)`、`int.parse(yuanStr) * 100`、`double.parse`、`.round()`、`toDouble()` 等浮点路径。显示走 `fenToYuan()`，解析走 `yuanToFen()`。
- **理由**：浮点累加会产生"1 分钱对不上账"，直接冲击导出/导入断言与「合计 == 明细之和」恒等式。
- **来源**：
  - `docs/03-数据模型与信息架构.md` **§4.6 金额精度**（`:376-380`）：「存储用**定点小数**（两位小数，货币最小单位"分"），**禁用浮点**（浮点累加产生"1 分钱对不上账"，直接冲击 AC-33 与导出导入断言 §6.5）」；**§6.2 规则 2**（`:457`）：「金额**以整数"分"序列化**（示例：24000 = 240.00 元）——彻底规避浮点；倍率同法（15 = 1.5 倍）」。
  - `docs/07-UI实现规格.md` **§1.1 金额显示**（`:57`）：「数据层与备份文件一律**整数「分」**（03 §4.6 / §6.2 规则 2）；UI 层只做**显示换算**，**绝不**把金额转成 `double` 参与任何运算或比较」；同节规则 2 明列禁令；**§1.2 倍率显示（整数「×10」）**：「存储 `int`（`15` = 1.5 倍）……**禁止** `x / 10`」。
  - `02-需求与验收.md` **§D.0.2 第 6 条** 与 **§F-8**（实名为 `fenToYuan`/`yuanToFen`，`app/lib/ui/widgets/money.dart:9,30`）。
- **日期**：2026-10-06（登记）· 基线约束（`03 §4.6` / `07 §1.1`）

## D-3 金额必须「快照」：改价目表不回改历史记录

- **决策**：每条工作记录在**首次固化**时写入**金额快照五件套**（`amountSnapshot` / `rateSnapshot` / `rateDetailSnapshot` / `qtySnapshot` / `qtyUnitSnapshot`）并**冻结**；**改价目表/计价规则不回改历史记录**。重算时 `rule` **必须由本条快照重建**，**绝不可读当前 `pricing_rule`**。改单价＝独立动作 A（改快照 + 仍 `auto`）；手工覆盖＝独立动作 B（`manual`）；改归属日 `workDate`＝**纯 Meta**（金额快照冻结不动）。
- **理由**：历史账目不可被后续规则变更追溯篡改（设计底线 ②）；快照是"当时的钱"的唯一凭证。
- **来源**：
  - `docs/03-数据模型与信息架构.md` 开篇底线（`:16`）与字段约定 `(快照) = 落库即固化、此后不改`（`:20`）；**§3.3 快照引用（非外键计算引用）**（`:270-281`）：「读取时**直接读 `金额快照`**，永不 join 规则」「规则改价 → 历史金额**不变**」；**实现红线**（`:281`）：「禁止任何"读取时用 pricing_rule 当前值重算 WorkRecord 金额"的代码路径——这是打破设计底线 2 的唯一途径」；**§4.1**（`:328-330`）与 **§4.5**（`:366-374`）：动作 A/B 与改归属日口径。

## D-4 剩余工资唯一口径 = 应收 − 已收（草稿不计入应收）

- **决策**：**剩余工资唯一口径 = 应收 − 已收**。其中：
  - **应收** = Σ `status ∈ {confirmed, settled}`（即「已确认 / 已结算」）且 `deleted_at IS NULL` 的 `amountSnapshot`；
  - **已收** = Σ `deleted_at IS NULL` 的 `amount`；
  - **草稿（draft）不计入应收**。
- **理由**：全产品只有一个剩余工资算法；草稿未确认，不构成应收（设计底线 ③）。
- **来源**：
  - `docs/03-数据模型与信息架构.md` 开篇底线（`:16`）：「③ 剩余工资**唯一口径**（基础版：`剩余 = 应收 − 已收`）」；**§5.1 算法**（`:386-396`）原文：
    ```text
    剩余(公司c) =
        Σ 工作记录(c, 状态 ∈ {已确认, 已结算}).金额快照
      − Σ 收款(c).金额
    ```
    并注「基础版无借支项」「全局剩余 = Σ 各公司剩余」「五处显示共用同一查询函数……派生不落库」；**§7 日历查询口径**（`:528`）：「状态 ∈ {已确认, 已结算} # **草稿排除（AC-32）**」。
  - `02-需求与验收.md` **§F-4**：「剩余唯一口径 = 应收 − 已收」（引 `02-PRD.md:186` §2.7、`:332` §4.4、`03:388-396` §5.1、`database.dart:304/313/324`）；**§F-5**：「草稿不计入应收」（引 `03 §8` 约束 1、AC-32、`database.dart:1263`）。
- **日期**：2026-10-06（登记）· 设计底线 ③

## D-5 公司名映射必须双 `true`；但页面主标签用全名 `name`（E-14 结论）

- **决策（两条）**：
  1. 展示历史数据（看板 / 公司列表 / 公司详情 / 欠款列表）时，公司元数据查询**必须显式** `listCompanies(includeDisabled: true, includeDeleted: true)`（**禁裸调** `listCompanies()`——其默认 `includeDisabled=false`、`includeDeleted=false`，会漏掉停用/归档公司 → 显示"未知公司"或**隐藏欠款**）。
  2. **页面公司主标签一律用全名 `company.name`**；`shortName` 非空时追加「（简称）」。**不用 `displayName`**（其非空取简称、否则取 `name` 前 2 字）。`displayName` 保留不删不改，留给 Wave C 的 P03 日历窄格使用。
- **理由**：
  - 双 `true`：「有账必列」（停用/归档公司显示并计入）是冻结要求；漏掉停用公司仍欠的钱会使**剩余显示偏小**，是本项目**唯一不可容忍的方向**。
  - 全名：`shortName` 全 App **无任何 UI 可写入**（新建写死 `null`、编辑框仅透传，**唯一可写路径是备份导入**），故 `displayName` 实际恒为 `name` 前 2 字 → 4 个页面主标签被截成 2 字，「某某建筑」与「某某劳务」分不清（**E-14**）。
- **来源**：
  - 双 `true`：`docs/07-UI实现规格.md` **§4.1 风险与 D2**（`:711` / `:718`）：「元数据来源 = `listCompanies(includeDisabled: true, includeDeleted: true)`……一份读法覆盖"启用 + 停用 + 已删"三类」；**§4.1 强制约束 1**（`:736`）：「**禁止**看板 / 公司列表出现 `listCompanies()` **裸调用**」；`02-需求与验收.md` **§F-7**。
  - 全名：`11-主理人裁定（WaveA设计）.md` **§9.2 / §9.3**（裁定 **R-14**）；`09-WaveA-实现设计.md` **§6.3.1**（勘误 **E-14**）。
- **日期**：2026-10-06

## D-6 聚合坏值（`FormatException`）不得白屏：降级 + 告警 + 导出引导 + 重试

- **决策**：看板/统计读取聚合时遇**脏值**（DB 层 `_asAggregateInt` 抛 `FormatException`）**不得白屏**。须：**降级呈现**（金额位标 `'—'`／「读取失败」，其余内容照常渲染）+ **顶部黄色告警条**（逐字「账目数字可能不完整，请勿据此对账」）+ **导出备份引导** + **重试**。本波采 `07 §4.4 **D5** 退让档`；理想档（行级隔离 `*Lenient`）顺延 Wave B。
- **理由**：脏数据不可整屏 `_ErrorView`（会连带隐藏可信的应收/卡片）；也不能静默（静默少算"已收"→ 剩余虚增，属唯一不可容忍方向）。必须让用户知道"这个数字不完整"。
- **来源**：
  - `docs/07-UI实现规格.md` **§4.4 I-9** —— **D3**（`:854`）：「看板数字免疫（DB 层实现 = 抛错，UI 必须 `catch`）……**看板必须 `catch` 该异常 → 降级呈现（应收可信、已收标"读取失败"）+ 顶部告警 + 引导导出备份**，不得冒到白屏」；**D5**（`:856`）：「降级路径……必须……说明"**账目数字可能不完整，请勿据此对账**"——诚实降级，不假装正常」；**D2**（`:853`）：「**不静默**：页面顶部**黄色告警条**……」。§7 **G-03**（`:942`）复述同一契约。
  - `02-需求与验收.md` **§D.0.3**（`:341`）：「聚合坏值 → `catch` `FormatException` → **降级呈现**（应收可信、已收标"读取失败"）+ 顶部告警 + 引导导出备份（**不白屏**）」（同款亦见 `§D.1:363`）。

## D-8 设计与实现纪律：不采信口头汇报 / 报告可被文件证伪 / 未签发裁定不得落地 / 先读后改

- **决策**：本项目一律遵守以下纪律：
  1. **不采信口头汇报与文档自述**——裁定前**独立核实**（读真实源码、跑 grep、自跑编译/单测）。
  2. **报告必须可被文件证伪**——每一处对代码的断言**必须带 `文件:行号`**（本项目**审查硬门槛**）；引用上游**逐字复制原文**，**禁止凭记忆转述**。

  4. **先读后改**——改动前必须读原文；裁定某线偏差前**必须先复读该线自己的原文**。
  5. **证据必须标注层级（实测 / 编译 / 读码）**——**同构推理 ≠ 实测**；私有成员无法从外部调用的，一律标注"同构推理 / 读码级"。
