# 01 · 需求理解与边界（阶段⓪ 产物）

> 项目：工时工资记账（暂定名 worklog-app）
> 路由：`路由=全流程`（多模块新项目，无既有代码库）
> 本轮范围：**需求闭环 + 概念设计**。实施与技术选型待用户另行启动。
> 日期：2026-09-30

---

## 一、一句话定位

给**受雇劳动者**（工人 / 零工 / 装修工 / 司机等）用的**个人双向台账**：
左边记「干了多少活、该拿多少」（应收），右边记「实际拿到多少」（已收），
差额即「剩余工资」。日历与统计都是同一份记录的派生视图。

> 关键澄清：它**不是计时器**，也不是老板侧派工系统。核心价值是**对账与欠薪感知**。

---

## 二、用户原话意图拆解

| 原话要点 | 理解 |
|---------|------|
| 针对不同公司做记录 | 多公司并行，每个公司一套计价规则（`公司` 为一等实体） |
| 对某天的工作进行记录 | 记录以**日期**为主键维度，日历是第一入口 |
| 时长或时间段 / 时价或日价 | 计价方式至少两种：按小时（可手填时长或填起止时间）、按天 |
| 日历形式看到哪些天做了工、对应哪些公司 | 日历格子需支持**一天多公司**的聚合展示 + 着色 |
| 详情看到几个记录、每条什么内容 | 日期 → 记录列表 → 单条详情，三级下钻 |
| 不同维度的汇总统计 | 至少：按公司 / 按月份 / 按时间段 / 按计价方式 |
| 拿到工资的记录，方便计算剩余工资 | **应收 − 已收 = 剩余**，这是本产品的差异化核心 |

---

## 三、已确认边界（用户拍板，见 00 台账 D1–D4）

- **D1 结算规则**：时价/日价 + 加班倍率 + 周末/节假日倍率 + 计件 + 提成 + 扣款 + 借支 + 月结账期。
  不含个税、社保代扣（见 Q10）。
- **D2 数据存放**：本地优先，离线可用；登录后可开启云备份 / 多端同步。
- **D3 主力设备**：手机为主（「收工随手记」是最高频场景）。
- **D4 使用范围**：自己用 + 可分享给工友；**各自独立账本，数据彼此不可见**。

## 五、明确排除（本轮不做）

- 个税、社保、公积金代扣代缴
- 老板侧派工 / 排班 / 多人协作编辑同一账本
- 与第三方考勤机、企业 ERP 对接
- 发票、报税凭证管理

---

## 六、设计底线（不得违反）

1. **日历与统计不另存汇总数据**，全部由记录实时派生——避免「日历 8 小时、统计 7.5 小时」的对不上账。
2. **金额必须快照**：记录落库时固化当时单价与算出金额；改价不影响历史（对应 P7）。
3. **剩余工资口径唯一**：`剩余 = 应收合计 − 已收合计`，全产品只有这一个算法，不许各处各算。（**二期引入借支后扩展为 `应收 − 已收 − 借支未还`**，见 02-PRD §13.3；基础版不含借支项，R-7 修复）
